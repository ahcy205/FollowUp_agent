- 브랜치: `feat/number-unit-checks`
- TDD: 실패하는 테스트 → 구현 → 통과. 기존 테스트 기대값은 바꾸지 않는다(바꿔야 하면 이유를 남긴다).

## Task 1: 단위 숫자 키 (`draft_checks.py`)
- [x] 테스트: `tokens("30만 원")`의 키가 `300000`, "1.5만" → 15000, "3천" → 3000, "2억" → 200000000, "8만 8천" → 88000, "1억 2천만" → 120000000, "3만 5천 500" → 35500.
- [x] 테스트: `draft_warnings("무료 배송 30만 원 이상", "메모: 300,000원 이상 무료", "")` → 경고 없음. 반대 방향도.
- [x] 테스트: 정수가 아닌 결과("1.23456만")는 단위 키로 보지 않는다. (→ 변경 #2, #3)
- [x] 구현: `_TOKEN_RE`의 숫자 갈래 뒤에 단위 꼬리를 읽어 값을 합친다. 날짜 · 일 · 월 갈래는 그대로.

## Task 2: 보일 글에 단위 말 (`draft_checks.py`)
- [x] 테스트: `draft_warnings("배송: 30만 원 이상", "", "")["unsupported"] == ["30만 원"]`, "1,500원" → "1,500원", "100개" → "100개".
- [x] 구현: `token_spans`가 돌려주는 보일 글에 바로 뒤 단위 말을 붙인다. 끝 위치(내부용 값의 '원' 확인용)는 지금 의미를 지킨다. (→ 변경 #4, #5)

## Task 3: 함께 쓰는 곳
- [x] 테스트(`test_reply_draft_sources.py`): 자료 줄 "300000"과 초안 "30만 원"이 인용 확인을 통과. 내부용 자료 "88000"이 초안 "8만 8천 원"에서 잡힌다.
- [ ] 테스트(검색): 검색어 "30만"이 "300,000"이 든 줄에 맞는다. (→ 변경 #1: 해당 없음)
- [x] `internal_values`의 '원' 붙이기와 새 보일 글이 겹치지 않는지 확인.

## Task 4: 마무리
