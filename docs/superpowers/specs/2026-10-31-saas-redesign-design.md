# 프리미엄 SaaS 리디자인 설계

- 작성일: 2026-10-31
- 상태: 사용자 승인(화면별 계획 · 결정 3가지, 2026-10-31)
- 바꾸는 것: [화면 전면 개편(견적서 양식)](2026-10-31-ui-redesign-design.md)의 시각 체계를 **전부 대체**한다 **(사용자 결정)**. 기능 · 상태 체계 · API 동작은 그대로.
- 참고: Superhuman(목록 · 키보드), Linear(상태 · 필터 · 상세 패널), Gmail Gemini(요약 · 답장), Intercom(AI 처리 상태). 복제하지 않고 재해석한다.

사용자 결정은 **(사용자 결정)**, 제가 정한 것은 **(내 판단)**으로 표시한다.

## 1. 목표
- 메일 확인 → 업무 처리 → 답장 → 후속 대응을 놓치지 않는 제품 경험.
- 업무 상태가 한눈에 구분되고, **AI가 한 일과 사용자가 할 일**이 분명히 나뉜다.
- 발송 안전장치를 하나의 체크리스트로 보여 준다.
- 데스크톱 우선, 태블릿 · 휴대폰 대응.

## 2. 지켜야 할 규칙 (사용자 지정, 백엔드 그대로)
1. 사용자가 고친 기한 · 중요도는 재분석으로 덮지 않는다.
2. 초안은 사용자 확인 없이 보내지 않는다.
3. 근거 없는 숫자 · 날짜는 "확인했어요" 전까지 보내기를 막는다(오탐 때문에 확인으로 풀 수 있다 — 현재 동작 유지, **(내 판단)**).
4. `[[ ]]` 빈칸이 남으면 보낼 수 없다.
5. 내부용 자료 값은 "알고 보냅니다" 확인을 요구한다.
6. 확인 뒤 초안이 바뀌면 다시 확인(서버 409).
7. 받는 사람이 바뀌면 다시 만들어야 한다(서버 409).
8. 근거 없는 재답장 변경은 반영하지 않는다.
9. 합치기는 10분 동안 되돌릴 수 있다.
10. 상태 전환 · 오류 처리 로직 유지.

## 3. 정보 구조
- 왼쪽 사이드바: **홈 · 받은 업무 · 후속 관리 · 자료실 · 설정** **(사용자 결정: 후속 관리를 메뉴로 따로)**.
- 받은 업무: 탭(처리할 일 · 답 기다림 · 참고용 · 완료)과 묶음(지금 처리 · 이번 주 · 나중에)은 그대로. 데스크톱(1200px 이상)은 **사이드바 · 목록 · 상세 패널 3단**, 업무를 누르면 오른쪽에 상세. 주소는 `/inbox/:id`, 예전 `/tasks/:id`도 같은 화면.
- 후속 관리: 받은 업무 응답에서 무응답 · 내용 바뀜 · 답장 안 함 업무와 답 기다림 업무를 모아 보는 목록(새 API 없음).
- 휴대폰: 한 단, 아래 탭 막대, 목록 → 상세는 쌓인다.
- 키보드: `j`/`k` 이동, `Enter` 열기, `Esc` 패널 닫기, `/` 목록 검색, `?` 단축키 안내.

## 4. 디자인 체계 (사용자 지정 방향)
- 화이트 · 라이트 그레이 바탕, 딥 네이비(글자 · 사이드바 · 주 버튼), 인디고-블루(선택 · 링크 · 주 동작). 상태색: 빨강(기한 지남 · 막힘), 황토(확인 필요), 초록(완료 · 준비됨). 그라데이션 · 보라 장식 없음.
- **AI 표시:** AI가 만든 값은 작은 "AI" 표지, 사용자가 정한 값은 "직접 정함", 확인이 필요한 값은 황토 표지.
- Pretendard, 숫자는 고정폭. 글자 단계 12 · 13 · 14 · 16 · 20 · 26.
- 공통 부품: 사이드바, 목록 행, 상세 패널, 상태 표지, 중요도 표시, 기한 칩, 발송 체크리스트, 변경 전후 카드, 빈 화면, 자리 표시, 알림 띠.

## 5. 화면
- **홈:** 숫자 칸 5개(오늘 처리할 업무 · 기한 임박 · 답장 대기 · 무응답 · 내용 바뀜 · 완료 중), AI 처리 상태(Gmail 마지막 확인 · 판별 대기 · 분석 실패 · 스위치), 새로 가져온 메일(판별 결과), 최근 업무 활동(새 API ①).
- **받은 업무:** 3단. 목록 행은 중요도 · 보낸 사람 · 요약 · 상황 표지 · 할 일 진행 · 기한. 목록 검색(화면 안 필터).
- **업무 상세:** 머리(제목 · 보낸 사람 · 상태 · 기한 · 동작), AI 요약 카드, 원하는 것, 중요도 · 기한(근거 문장), 할 일, 변경 이력(전 → 후 · 근거 · 되돌리기 · 반영하기), 답장, 원본 메일, 처리 기록.
- **답장 초안:** 받는 사람(서버가 정함, 잠금 표시) · 참조 · 제목 · 본문, 자료에서 가져온 값 · 참고한 자료, **발송 체크리스트**(빈칸 · 근거 없는 값 · 내부용 값 · 참고 자료 · 받는 사람 · 그사이 변경) — 모두 통과해야 "이대로 보내기".
- **후속 관리:** 무응답 3영업일 · 내용 바뀜 · 답장 안 함 묶음, 각 행에서 상세로.
- **자료실:** 표(이름 · 형식 · 크기 · 올린 날 · 공유 등급 · 상태), 상세 패널(새 API ②: 덩어리 내용 · 참고한 초안), 검색 시험(새 API ③).
- **설정:** Google 연결 카드(상태 · 주소 · 권한 · 마지막 확인 · 만료 안내), 기능 스위치 상태(읽기 전용, 바꾸는 방법 안내), 브라우저 알림.

## 6. 백엔드 추가 (사용자 승인: 전부, 모두 읽기 전용)
- ① `GET /api/activity?limit=` — 내 메일 업무의 최근 처리 기록(업무 번호 · 제목 · 기록 종류 · 한 줄 요약 · 위험도 · 시각). 메일 본문 · 주소는 넣지 않는다(타임라인 한 줄 요약 규칙).
- ② `GET /api/knowledge/sources/{id}` — 자료 정보 + 덩어리(순번 · 줄 · 의심 표시) + 그 자료를 참고한 초안(업무 번호 · 제목 · 초안 상태). 남의 자료는 404. 스위치가 꺼져도 볼 수 있다(목록과 같음).
- ③ `POST /api/knowledge/search` `{q}` — 답장 초안이 쓰는 것과 같은 검색으로 "답장에 써도 됨" 자료에서 찾는 결과를 미리 본다. 검색어를 주소에 남기지 않으려고 POST. 스위치가 꺼지면 409. 호출 횟수 제한.
- 개인정보 흐름 변화 없음(모두 내 PC 안, 외부 전송 없음).

## 7. 확인
- 백엔드 테스트(새 API 테스트 포함), 프론트 빌드 · lint.
- 점검 서버에서 데스크톱(1440) · 태블릿(900) · 휴대폰(390), 모든 버튼 · 단축키 · 발송 체크리스트.
- 디자인 리뷰 1회, 코드 리뷰 1회.
