## 1. 목적
- 처음 연 사람이 "이 앱을 왜 써야 하는지" 바로 안다: 첫 화면이 오늘 기준 업무 대장이다. **(사용자 결정: 목표)**
- AI가 만든 화면처럼 보이지 않는다: 보라 강조, 그라데이션, 이모지 아이콘, 그림자 카드 반복을 없앤다. **(사용자 결정)**
- PC와 휴대폰 반반으로 쓴다. 두 화면을 같은 비중으로 설계한다. **(사용자 결정)**

### 하지 않는 것
- API · DB · 비즈니스 로직 변경. 화면은 기존 응답만 쓴다.
- 생성 이미지 · 일러스트(ComfyUI 등). **(사용자 결정)**
- 새 UI 라이브러리. 글꼴 하나(Pretendard)만 더한다. **(내 판단: 한국어 업무 화면의 표준 글꼴이고, 지금도 지정만 돼 있고 설치되지 않은 PC에서는 맑은 고딕으로 떨어진다)**

## 2. 세계 (사용자 결정: 견적서 · 거래명세서 양식)
- 흰 서식 용지 위 구획선 · 라벨 칸 · 기입란. 페이지는 카드 더미가 아니라 **용지 한 장**과 그 안의 구획.
- 색: 잉크 흑청(본문), 회색 라벨 칸, 인주 주홍 하나(보내기 · 확정, 기한 지남, 지금 처리), 청색 볼펜(링크 · 선택 · 포커스). 완료는 차분한 초록, 확인 필요는 황토.
- 중요도: 상 · 중 · 하 글자 칸(색만으로 구분하지 않음). **(내 판단: 지금의 반쪽 채운 점은 범례 없이는 읽히지 않는다)**
- 모서리 2px, 그림자는 용지 한 장에만 아주 옅게. 아이콘은 직접 그린 SVG(선 1.5px).
- 서명 동작: 답장을 보내거나 업무를 완료하면 주홍 도장("보냄" · "완료")이 찍힌다.

## 3. 화면별 변경
### 3.1 틀
- 위 막대: 새 로고(주홍 사각 도장 "FU"), 메뉴는 밑줄형. 휴대폰(640px 이하)에서는 메뉴가 **아래 탭 막대**로 내려간다. **(내 판단: 한 손 조작)**
- Google 연결 만료 띠는 그대로(색만 새 체계).

### 3.2 받은 업무 (첫 화면)
- 맨 위: 기준일(오늘 날짜) · Gmail 상태 · 마지막 확인 · [지금 확인].
- 합계 칸 띠: 지금 처리(가장 크게, 주홍) · 이번 주 · 나중에 · 답 기다림.
- 탭(처리할 일 · 답장 보냄 · 참고용 · 완료)은 밑줄형, 숫자 포함.
- 목록은 **업무 대장 표**: 중요 · 기한 · 상대 · 업무 요약 · 할 일 · 상황. 처리할 일 탭은 "지금 처리 / 이번 주 / 나중에" 묶음 머리 줄. 행 전체가 링크.
- 휴대폰: 행이 두 줄(상대 · 기한 / 요약 · 상황)로 접힌다.
- 빈 화면 · 불러오는 중(줄 모양 자리 표시) · 오류 상태를 설계한다.
- 나중에 보기 · 업무 아님 메일은 접는 구획으로 그대로.

### 3.3 업무 상세 (메일 업무)
- 순서: 안내 띠 → 제목 · 상태 도장 → **업무 양식**(상대 · 받은 날 · 원하는 것 · 바뀐 내용 · 중요도 · 기한과 근거 · 캘린더) → **할 일** → **답장**(초안 카드) → 그 밖의 동작 → 원본 메일. **(내 판단: 할 일을 끝내고 답장하는 흐름에 맞춰 초안을 할 일 아래로 옮긴다)**
- 메일 업무에서는 "Agent Activity" 상자를 없애고 옆 칸에 **처리 기록**(타임라인)만 둔다. 목표 입력 Agent 업무는 지금처럼 실행 상태 · 토큰 사용량을 보인다. **(내 판단: 메일 업무에는 실행이 없어 늘 "사용자가 처리할 업무"만 보였다)**
- 답장 초안: 받는 사람 · 참조 · 제목을 양식 칸으로, 본문은 기입란. 경고 · 자료 출처는 칸 아래 비고란. 보내기 확인 단계는 그대로(화면 안).
- 알려진 표시 버그 수정: 초안 본문 · 입력칸 글자가 굵게 나오던 것, 참조 체크박스 배치가 깨지던 것.

### 3.4 그 밖의 화면
- 로그인: 왼쪽에 **예시 업무 대장**(가상 데이터, "예시" 표시)으로 제품이 하는 일을 보여 주고, 오른쪽에 로그인 양식. 이모지 목록은 없앤다.
- 자료실 · 설정 · 전체 업무 · 워크스페이스: 같은 양식 체계로 다시 입힌다. 동작은 그대로.

## 4. 확인
- `npm run build` · `npm run lint`, 백엔드 테스트(화면만 바꾸므로 그대로 통과해야 함).
- 가상 데이터 DB로 띄운 점검 서버에서 PC(1440) · 휴대폰(390) 화면을 한 번에 확인하고, 고친 뒤 한 번 더 확인한다.
- 주요 동작: 탭 전환, 업무 열기, 할 일 체크, 기한 수정, 초안 확인 단계, 자료 올리기 화면, 설정.
